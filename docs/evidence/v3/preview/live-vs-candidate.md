# Live production vs V3 candidate: legacy tool compatibility (2026-10-22)

Baseline: live production `https://soren-shared-mcp-skills.vercel.app/api/mcp` (2.4.0). Candidate: a local production build (`next start`) of branch commit `c5bcc01` from a clean clone, with `SOREN_V3_TOOLS=1` and **no gateway store or rate key**. Raw report: `live-vs-local-flag-on.json`, generated by `scripts/compare-mcp-endpoints.mjs`. All calls were read-only. Each external-discovery tool was called at most once per endpoint.

**Scope limit:** this is not the isolated Vercel preview required by Gate 5. That preview is blocked because the Vercel CLI on this machine is logged out. The candidate ran over loopback, without Vercel OIDC, so `skills_sh` reports `configured:false`; on Vercel it reports `true` when OIDC is available.

|---|---|---|---|
| Server identity | `soren-universal-skill-router` 2.4.0 | same name, 2.5.0 | Expected version bump |
| Tools | 8 | 14 (legacy 8 first, same order) | Additive |
| Annotations, required fields (8 legacy tools) | — | identical for all 8 | Compatible |
| Schema properties | — | none removed; `route_task` +5 optional, `read_skill` +1 optional | Additive |
| Skill resources | 14 | 22 (all 14 live URIs kept, 8 added) + 52 V3 resources | Additive |

| `search_skills` local "keyboard WCAG" | accessibility | accessibility | Same |
| `route_task` local, 10 tasks | — | 8 same primary; 2 changed; response keys identical in all 10 | See below |
| `list_providers` | 3 agent integrations | 13 agent integrations | Additive field content |
| Path traversal (`read_skill`, `inspect_candidate`) | rejected | rejected | Same |
| Cross-origin browser request | 403 | 403 | Same |

Changed `route_task` primaries, both toward a more specific new skill:
- "Optimize a glTF model with Draco": `mcp-integration` → `gltf-asset-pipeline`.
- "Build a shader material with TSL": `threejs-production` → `shader-material-lab`.

## Behavior differences that need an owner decision

| Behavior | Live 2.4.0 | Candidate without store |
|---|---|---|
| Federated `route_task` | providers called; 8 candidates (skillsmp timed out) | all providers `shared_provider_budget_unavailable`; 0 candidates; local recommendations still returned |
| `discover_skills` (skillsmp) | ok, 3 results | `unavailable`, `shared_provider_budget_unavailable` |
| `search_mcp_servers` | ok, 2 results | tool error `shared_provider_budget_unavailable` |
| Malformed `Authorization` header | 200 (ignored) | 401 |
| Well-formed bearer token | 200 (ignored) | 503 `private_identity_unavailable` |
| 17 KB request body | 200 | 413 |

The candidate's fail-closed behavior is intended, but deploying it to production without the shared gateway store would visibly degrade external discovery and reject bearer-carrying clients. `docs/v3/production-activation.md` lists the store requirements and the owner's choice.
